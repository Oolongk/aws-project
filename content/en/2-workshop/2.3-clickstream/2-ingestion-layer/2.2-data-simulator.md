To provide the system with input data for AI training, I have built a Clickstream data simulator using Python. This simulator models the behavior of 3 user groups (Personas) with different weights, creating a dataset with realistic patterns.

#### Step 0: Create dedicated User and Get security key (Best Practice)

To ensure absolute safety for the system (Principle of Least Privilege), we will NOT use the Admin account. Instead, I will create a dedicated anonymous IAM User that only has permission to push data to Kinesis Firehose.

| Step | Action | Technical details |
| :--- | :--- | :--- |
| **1** | Access IAM | In the AWS Console, type to search **IAM** -> Select **Users** -> Click **Create user**. |
| **2** | Identify User | Name the User `Clickstream-Data-Pusher` and click Next. |
| **3** | Authorize (Least Privilege) | Select **Attach policies directly**. Find and check the `AmazonKinesisFirehoseFullAccess` policy. Click Next -> Create user. |
| **4** | Open security tab | Click on the newly created user name `Clickstream-Data-Pusher`, switch to the **Security credentials** tab. |
| **5** | Create new key | Scroll down to the **Access keys** section, click the **Create access key** button. Select **Local code**, confirm and click Next. |
| **6** | Store key | The screen displays `Access key` and `Secret access key`. Please copy these two strings to paste into the Python code below. |

> **Security Alert:** The `Secret access key` string is ONLY displayed EXACTLY ONCE at this step. Absolutely do not share or upload this key pair to open source repositories (like GitHub Public) to avoid account leakage. Please delete this key pair on the IAM interface immediately after completing the project.

#### Simulator source code (Python)

This is the core code that generates Clickstream events distributed by Persona. The source code has been integrated with error trapping blocks to stop safely:

```python
import boto3
import json
import time
import random
import datetime

# ----------------------------------------------------------------------
# [SECURITY ALERT] 
# Remember to delete the Key after completing the project to avoid wasting money!
# ----------------------------------------------------------------------
ACCESS_KEY = 'YOUR_AWS_ACCESS_KEY'
SECRET_KEY = 'YOUR_AWS_SECRET_KEY'
REGION = 'ap-southeast-1'
STREAM_NAME = 'clickstream-delivery-stream' 

# Initialize direct connection with Kinesis Firehose
client = boto3.client(
    'firehose',
    region_name=REGION,
    aws_access_key_id=ACCESS_KEY,
    aws_secret_access_key=SECRET_KEY
)

def generate_news_persona_event():
    # AI Algorithm: Divide ratio of 3 groups of newspaper readers (30% Tech, 30% Finance, 40% GenZ)
    persona = random.choices(['Tech_Bro', 'Finance_Investor', 'GenZ_Fan'], weights=[0.3, 0.3, 0.4])[0]
    
    if persona == 'Tech_Bro':
        # Group 1: Tech People - Only use MacOS/Windows, like to read Tech/AI news
        user_id = str(random.randint(1000, 1999))
        device = random.choices(['MacOS', 'Windows'], weights=[0.6, 0.4])[0]
        url = random.choices(['/tech/ai-chatgpt', '/startup/kydang', '/tech/aws-cloud'], weights=[0.5, 0.2, 0.3])[0]
        
    elif persona == 'Finance_Investor':
        # Group 2: Investor People - Use iOS a lot, like to read Stock/Real Estate news
        user_id = str(random.randint(2000, 2999))
        device = random.choices(['iOS', 'Windows'], weights=[0.8, 0.2])[0]
        url = random.choices(['/finance/stock-market', '/real-estate/vinhomes'], weights=[0.6, 0.4])[0]
        
    else:
        # Group 3: Gen Z Entertainment - Use Android/iOS, like Showbiz/K-pop news
        user_id = str(random.randint(3000, 3999))
        device = random.choices(['Android', 'iOS'], weights=[0.7, 0.3])[0]
        url = random.choices(['/entertainment/kpop-news', '/music/youtube-trending'], weights=[0.6, 0.4])[0]

    # Package data in AWS Glue Schema format
    return {
        'user_id': user_id,
        'event_type': 'page_view', # Newspaper reading behavior is mainly page view
        'event_timestamp': datetime.datetime.now().strftime('%Y-%m-%d %H:%M:%S'), 
        'page_url': url,
        'device_os': device
    }

print("=========================================================")
print(f"🚀 Start broadcasting Newspaper (Persona) data to {STREAM_NAME}...")
print("=========================================================\n")

events_sent = 0

try:
    while True:
        event = generate_news_persona_event()
        # Turn Dict into JSON string, add \n so Firehose cuts lines correctly
        data_as_string = json.dumps(event) + '\n'
        
        # Shoot data to AWS
        client.put_record(
            DeliveryStreamName=STREAM_NAME,
            Record={'Data': data_as_string}
        )
        
        events_sent += 1
        
        # Print log to screen beautifully and easy to track
        print(f"[Log] Sent: Reader {event['user_id']} ({event['device_os']}) is reading {event['page_url']}")
        
        # Stop for 0.1s (Equivalent to 10 events/second) - Enough to accumulate data without taking up much space
        time.sleep(0.1) 

except KeyboardInterrupt:
    print(f"\n🛑 System stopped! A total of {events_sent} newspaper readings were sent to the Data Lake.")
```
