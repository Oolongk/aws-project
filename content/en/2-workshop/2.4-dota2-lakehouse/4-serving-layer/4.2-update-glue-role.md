In Chapter 2, the AWS Glue IAM Role was only granted permissions to work with S3. Now, because the Glue Job needs to write data directly to DynamoDB, you need to grant it these additional permissions.

| Step | Action | Technical Details |
|---|---|---|
| 1 | Access IAM Role | Open the **IAM** service > Select **Roles** > Find and click the `Glue_Dota2_Processing_Role` you created earlier. |
| 2 | Add Permissions | In the *Permissions* tab, click the **Add permissions** button > Select **Create inline policy**. |
| 3 | Configure JSON | Switch to the **JSON** tab and paste the DynamoDB write permissions code below. (Remember to replace `YOUR_ACCOUNT_ID` with your AWS account ID). |
| 4 | Name the Policy | Click **Next**. Set the Policy name to: `DynamoDB_Write_Dota2_Metrics`. |
| 5 | Complete | Click **Create policy** to apply the new permissions to AWS Glue. |

JSON Inline Policy Code:

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "dynamodb:PutItem",
                "dynamodb:BatchWriteItem",
                "dynamodb:UpdateItem"
            ],
            "Resource": "arn:aws:dynamodb:ap-southeast-1:YOUR_ACCOUNT_ID:table/dota2_hero_metrics"
        }
    ]
}
```
