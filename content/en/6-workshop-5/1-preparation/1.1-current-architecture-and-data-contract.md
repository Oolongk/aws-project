The architecture is divided into a Data Lake path and a Serving path. The bridge between them is Lambda QMJ Loader: S3 creates new Parquet files, S3 sends an `ObjectCreated` event, and Lambda reads the file and writes items to DynamoDB.

## Data Flow

````text
Data Lake path
Sources → Backfill/Daily Ingestion → S3 Raw → Glue PySpark QMJ → S3 Processed

Serving path
S3 Processed -- ObjectCreated (*.parquet) --> Lambda QMJ Loader --> DynamoDB
DynamoDB --> Lambda Reader --> API Gateway --> Browser

Automation path
EventBridge Scheduler - - -→ Glue Python Shell Daily Ingestion
````

## Data Contract

| Dataset | Grain | Output location | Consumer |
|---|---|---|---|
| `us_prices_raw.parquet` | `ticker + price_date` | `raw_us_market/YYYY/MM/DD/` | Glue PySpark QMJ |
| `us_company_info.parquet` | `ticker + snapshot_date` | `raw_us_market/YYYY/MM/DD/` | Glue PySpark QMJ |
| `us_financials_raw.parquet` | `ticker + report_date + period_type + snapshot_date` | `raw_us_market/YYYY/MM/DD/` | Glue PySpark QMJ |
| QMJ output Parquet | One row per `ticker` at `AS_OF_DATE` | `processed_qmj/as_of_date=.../` | Lambda QMJ Loader |
| DynamoDB item | `ticker + snapshot_date` | Table `qmj_screener` | Lambda Reader |

> **Architectural Principle – Event-Driven Serving.** `qmj_transform.py` does not have `PutItem` or `BatchWriteItem`. The transform completes at S3 Processed; Lambda Loader is responsible for loading DynamoDB after detecting new Parquet files.
