To free the system from manually triggered tasks, we will use **AWS Step Functions Workflow Studio** to build a fully automated process in a sequential chain.

#### Step 1: Initialize AWS Glue Crawler to scan data

Before Step Functions can orchestrate, we need an automated tool to identify new Parquet files landing on S3 to update the ledger (Data Catalog).

| Step | Action | Technical details |
| :--- | :--- | :--- |
| **1** | Search service | In the AWS Console search bar, type **Glue** and select **Crawlers**. |
| **2** | Create Crawler | Click the **Create crawler** button, name it `Clickstream_S3_Crawler`. |
| **3** | Add data source | Click **Add a data source**, select S3 and point the absolute path to the raw data folder: `s3://your-bucket-name/data/`. |
| **4** | Configure IAM permissions | Select **Create new IAM Role** for AWS to automatically grant S3 read permissions for the Crawler. |
| **5** | Specify Database | In the Output configuration section, create a new Database named `clickstream_db`. |
| **6** | Complete | Click **Create crawler** to save the configuration. |

#### Step 2: Set up State Machine chain to prevent Race Condition

We proceed to assemble the services into an automated chain through the intuitive drag-and-drop interface of Step Functions.

| Step | Action | Technical details |
| :--- | :--- | :--- |
| **1** | Create State Machine | Go to the **Step Functions** service -> Click **Create state machine** -> Select **Workflow Studio** (Drag and drop). |
| **2** | Drag Crawler block | In the left filter, type `Glue` -> Drag the **Glue StartCrawler** block and drop it at the starting point (`Start`). In the right configuration column, enter the crawler name: `Clickstream_S3_Crawler`. |
| **3** | Insert Wait State | In the left filter, type `Wait` -> Drag the **Wait State** block (clock icon) and drop it **RIGHT AFTER** the Crawler block. Set the time to **120 Seconds**. |
| **4** | Drag Lambda block | In the left filter, type `Lambda` -> Drag the **Lambda Invoke** block and drop it after the Wait block. Point the target function to the `AthenaETLProcessor` function (will be created in section 3.2). |
| **5** | Drag SNS block | In the left filter, type `SNS` -> Drag the **SNS Publish** block and drop it at the end of the processing flow. Select the Topic ARN pointing to `Pipeline_Completion_Alert` prepared in Chapter 1. |
| **6** | Save and Deploy | Click **Save** in the top right corner to save the Conductor diagram. |

> **System Error Alert (Race Condition):** Adding the **Wait State (120 seconds)** block is a mandatory infrastructure engineering technique. AWS Glue Crawler takes an average of 1 to 2 minutes to scan the S3 hard drive and successfully update the table structure into the Data Catalog. Meanwhile, the AWS Lambda compute robot operates very quickly (takes only 3 seconds). Without the Wait State blocking block, Lambda will jump into executing the SQL query immediately while the data ledger is empty, leading to your output CSV file being completely blank.

#### Step 3: Schedule automatic running with Amazon EventBridge Scheduler

The current AWS interface has separated the scheduling feature into a powerful dedicated tool called **EventBridge Scheduler**. We will use this tool to wake up the Conductor.

| Step | Action | Technical details |
| :--- | :--- | :--- |
| **1** | Access Scheduler | Go to the **Amazon EventBridge** service -> Look at the left menu, find the **Scheduler** section and select **Schedules**. |
| **2** | Create Schedule | Click the **Create schedule** button. |
| **3** | Name it | In the Schedule name box, enter the name `Trigger-NewsPipeline-Hourly`. |
| **4** | Configure time | In the *Schedule pattern* section, select **Recurring schedule**. Continue to select **Rate-based schedule**, enter the number `1` and the unit as `Hours` (The system automatically runs once an hour). Scroll down and click Next. |
| **5** | Specify Target | On the Target detail page, find and select **AWS Step Functions** -> Select API **StartExecution**. In the *State machine* box, point to the Conductor name you just drew in Step 2. Scroll down and click Next. |
| **6** | Permissions & Complete | On the Settings page, in the *Permissions* section, keep the **Create new role for this schedule** option for AWS to automatically grant permissions. Click **Create schedule**. |
