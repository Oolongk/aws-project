Phục vụ dữ liệu

Thực hiện khởi tạo bảng lưu trữ trên Amazon DynamoDB để chứa dữ liệu Meta của các vị Tướng.

Bước Hành động Chi tiết kỹ thuật
1 Truy cập DynamoDB Trên thanh tìm kiếm AWS Console, gõ DynamoDB > Chọn Tables ở menu trái > Nhấn Create table.
2 Cấu hình Table Name Table name: dota2_hero_metrics.
3 Cấu hình Khóa chính Partition key (Khóa phân vùng): Gõ hero_id và chọn kiểu dữ liệu là String (S). Sort key là match_date và chọn kiểu dữ liệu String (S).
4 Cấu hình Settings Tại mục Table settings, tích chọn Customize settings để cấu hình tối ưu chi phí.
5 Tối ưu Capacity Mode Tại mục Read/write capacity mode, tích chọn On-demand (Pay-per-request).
6 Hoàn tất Cuộn xuống cuối trang và nhấn nút Create table màu cam.

Ở Chương 2, IAM Role của AWS Glue chỉ mới có quyền làm việc với S3. Bây giờ, vì Glue Job sẽ phải ghi dữ liệu trực tiếp vào DynamoDB, em cần cấp thêm quyền hạn này cho nó.

Bước Hành động Chi tiết kỹ thuật
1 Truy cập IAM Role Mở dịch vụ IAM > Chọn Roles > Tìm kiếm và click vào role Glue_Dota2_Processing_Role em đã tạo trước đó.
2 Thêm Permissions Tại tab Permissions, nhấn vào nút Add permissions > Chọn Create inline policy.
3 Cấu hình JSON Chuyển sang tab JSON và dán đoạn mã phân quyền ghi dữ liệu DynamoDB bên dưới vào. (Nhớ thay đổi vùng YOUR_ACCOUNT_ID thành ID tài khoản AWS của em).
4 Đặt tên Policy Nhấn Next. Đặt tên cho Policy này là: DynamoDB_Write_Dota2_Metrics.
5 Hoàn tất Nhấn Create policy để áp dụng quyền mới cho AWS Glue.

Mã JSON Inline Policy:

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "dynamodb:PutItem",
                "dynamodb:BatchWriteItem",
                "dynamodb:UpdateItem"
            ],
            "Resource": "arn:aws:dynamodb:ap-southeast-1:YOUR_ACCOUNT_ID:table/dota2_hero_metrics"
        }
    ]
}

Em tiến hành nâng cấp mã nguồn PySpark của AWS Glue Job. Ngoài nhiệm vụ lưu trữ file Parquet xuống S3, Glue sẽ tính toán trực tiếp tỷ lệ thắng (Winrate), tỷ lệ chọn (Pickrate) và dùng thư viện boto3 để đẩy thẳng kết quả vào DynamoDB.

Bước Hành động Chi tiết kỹ thuật
1 Mở Glue Studio Vào AWS Console > Tìm dịch vụ AWS Glue > Mục ETL Jobs > Chọn Visual ETL hoặc mở trực tiếp mã nguồn của Job dota2_etl_job đã tạo ở bài 2.3.
2 Cập nhật Script Chọn tab Script, xóa toàn bộ mã nguồn cũ đi và thay thế bằng đoạn code PySpark nâng cấp ở bên dưới.
3 Cấu hình tham số Đảm bảo các biến RAW_PATH, PROCESSED_PATH và tên bảng DynamoDB đã khớp với hệ thống của em.
4 Lưu và Chạy Nhấn Save > Nhấn Run để khởi chạy pipeline tính toán tổng hợp.
5 Kiểm duyệt kết quả Truy cập DynamoDB Console > Mục Tables > Chọn bảng dota2_hero_metrics > Nhấn nút Explore table items để kiểm tra các bản ghi metrics của các Hero đã được nạp thành công.

Mã nguồn PySpark nâng cấp (dota2_etl_job_v2.py):

import sys
import boto3
from pyspark.context import SparkContext
from awsglue.context import GlueContext
from pyspark.sql.functions import explode, col, from_unixtime, to_date, count, sum as _sum, when, lit

sc = SparkContext.getOrCreate()
glueContext = GlueContext(sc)
spark = glueContext.spark_session

RAW_PATH = "s3://dota2-raw-zone-tencuaban/raw_matches/"
PROCESSED_PATH = "s3://dota2-processed-zone-tencuaban/matches_parquet/"
DYNAMODB_TABLE = "dota2_hero_metrics"

# 1. Đọc dữ liệu thô và Flattening
df = spark.read.json(RAW_PATH)
df_exploded = df.select(
    col("match_id"),
    to_date(from_unixtime(col("start_time"))).alias("match_date"),
    explode(col("players")).alias("player")
)
df_final = df_exploded.select(
    "match_id",
    "match_date",
    col("player.hero_id").alias("hero_id"),
    col("player.win").alias("is_win")
)

# [Tối ưu Chương 2]: Ghi dữ liệu sạch lưu vết dài hạn dưới dạng Parquet Snappy xuống S3
df_final.write.mode("append").partitionBy("match_date").parquet(PROCESSED_PATH, compression="snappy")

# 2. [Nâng cấp Chương 4]: Tính toán Aggregation Metrics bằng Spark DataFrame API
print("Đang tính toán tổng hợp tỷ lệ Winrate và Pickrate của các Hero...")
total_matches = df.count()

df_metrics = df_final.groupBy("hero_id").agg(
    count("match_id").alias("total_picks"),
    _sum(when(col("is_win") == True, 1).otherwise(0)).alias("total_wins")
)

# Tính toán tỷ lệ phần trăm dữ liệu
df_metrics = df_metrics.withColumn("win_rate", (col("total_wins") / col("total_picks")) * 100) \
                       .withColumn("pick_rate", (col("total_picks") / lit(total_matches)) * 100)

# 3. Đẩy dữ liệu sang DynamoDB sử dụng boto3 kết hợp với phân vùng tính toán của Spark
def upload_row_to_dynamodb(row):
    # Khởi tạo boto3 client bên trong từng Worker Node của Spark Cluster
    dynamodb = boto3.resource('dynamodb', region_name='ap-southeast-1')
    table = dynamodb.Table(DYNAMODB_TABLE)
    
    # Thực hiện hành động Upsert dữ liệu (Ghi mới hoặc cập nhật nếu trùng hero_id)
    table.put_item(
        Item={
            'hero_id': int(row['hero_id']),
            'total_picks': int(row['total_picks']),
            'total_wins': int(row['total_wins']),
            'win_rate': str(round(row['win_rate'], 2)), # Ép sang chuỗi để tránh lỗi định dạng Float trong DynamoDB
            'pick_rate': str(round(row['pick_rate'], 2))
        }
    )

# Gọi hàm thực thi phân tán trên toàn bộ các dòng của DataFrame
print("Bắt đầu nạp dữ liệu phân tán vào Amazon DynamoDB...")
df_metrics.rdd.foreach(upload_row_to_dynamodb)
print("Nạp dữ liệu hoàn tất!")

Dữ liệu phân tích dù có hữu ích đến mấy cũng sẽ mất đi giá trị nếu hệ thống mất tới vài phút để hiển thị cho người dùng.

Trong chương này, em sẽ xây dựng Speed Layer cho hệ thống bằng cách sử dụng cơ sở dữ liệu NoSQL Amazon DynamoDB. AWS Glue PySpark sau khi xử lý dữ liệu sạch sẽ trực tiếp tính toán sẵn các chỉ số Meta (Aggregated Metrics) và nạp thẳng vào DynamoDB, đảm bảo ứng dụng Frontend có thể truy xuất thông tin với độ trễ dưới 100ms.

Em sẽ xây dựng một hàm Lambda đóng vai trò là API Backend chịu trách nhiệm tiếp nhận tham số hero_id gửi lên từ trình duyệt, truy vấn vào DynamoDB và trả về kết quả JSON.

Bước Hành động Chi tiết kỹ thuật
1 Truy cập AWS Console Tìm kiếm dịch vụ Lambda trên thanh công cụ.
2 Khởi tạo Hàm Chọn Functions ở menu trái > Nhấn nút Create function màu cam.
3 Cấu hình cơ bản Chọn Author from scratch. Function name: dota2-backend-api. Runtime: Chọn Python 3.9 (hoặc bản mới hơn).
4 Cấu hình Permissions Mở rộng mục Change default execution role > Chọn Create a new role with basic Lambda permissions (AWS sẽ tự tạo một Role cơ bản bảo mật). Nhấn Create function.
5 Gắn quyền đọc DynamoDB Sang tab Configuration > Mục Permissions > Chọn đường link Role name màu xanh. Hệ thống sẽ chuyển sang tab IAM.
6 Thêm Inline Policy Nhấn Add permissions > Create inline policy > Chọn tab JSON và dán đoạn mã bên dưới vào (Nhớ sửa YOUR_ACCOUNT_ID thành ID tài khoản AWS của em) > Đặt tên policy: DynamoDB_Read_Dota2_Metrics > Nhấn Create policy.
7 Viết mã nguồn API Quay lại tab Lambda Function > Kéo xuống phần Code editor, xóa sạch code mặc định và dán đoạn mã Backend Python bên dưới vào > Nhấn nút Deploy màu cam.

Mã JSON Policy cấp quyền đọc cho Lambda:

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "dynamodb:GetItem"
            ],
            "Resource": "arn:aws:dynamodb:ap-southeast-1:YOUR_ACCOUNT_ID:table/dota2_hero_metrics"
        }
    ]
}

Mã nguồn Python của Lambda:

import json
import boto3

DYNAMODB_TABLE = "dota2_hero_metrics"

def lambda_handler(event, context):
    print("Received event:", json.dumps(event))
    
    # 1. Trích xuất tham số hero_id từ đường dẫn API Gateway (Query String hoặc Path Parameter)
    query_params = event.get('queryStringParameters') or {}
    hero_id = query_params.get('hero_id')
    
    if not hero_id:
        return {
            'statusCode': 400,
            'headers': {
                'Access-Control-Allow-Origin': '*', # Bật CORS chống lỗi chặn Browser
                'Content-Type': 'application/json'
            },
            'body': json.dumps({'error': 'Tham số hero_id là bắt buộc!'})
        }
    
    # 2. Truy vấn dữ liệu trực tiếp từ Amazon DynamoDB theo Key Lookups
    dynamodb = boto3.resource('dynamodb', region_name='ap-southeast-1')
    table = dynamodb.Table(DYNAMODB_TABLE)
    
    response = table.get_item(Key={'hero_id': int(hero_id)})
    item = response.get('Item')
    
    if not item:
        return {
            'statusCode': 404,
            'headers': {'Access-Control-Allow-Origin': '*', 'Content-Type': 'application/json'},
            'body': json.dumps({'message': f'Không tìm thấy dữ liệu cho Hero ID {hero_id}'})
        }
        
    # 3. Trả kết quả JSON sạch về cho Frontend
    return {
        'statusCode': 200,
        'headers': {
            'Access-Control-Allow-Origin': '*',
            'Content-Type': 'application/json'
        },
        'body': json.dumps(item)
    }

Em tiến hành thiết lập một cổng API Gateway để chuyển đổi hàm Lambda Backend thành một địa chỉ URL công khai (Endpoint) trên Internet.

Bước Hành động Chi tiết kỹ thuật
1 Mở API Gateway Tìm kiếm dịch vụ API Gateway trên AWS Console.
2 Chọn loại API Tìm đến mục HTTP API > Nhấn nút Build màu cam (HTTP API rẻ và nhanh hơn REST API gấp nhiều lần).
3 Cấu hình Integrations Nhấn Add integration > Chọn Lambda. Chọn Region ap-southeast-1 > Ô Lambda function, chọn dota2-backend-api > API name điền: dota2-public-api > Nhấn Next.
4 Định tuyến Routes Configure routes: Method chọn GET. Path điền: /metrics. Target giữ nguyên hàm Lambda. Nhấn Next.
5 Giữ nguyên Stage Mục Stages giữ mặc định là $default (bật tính năng Auto-deploy). Nhấn Next.
6 Hoàn tất Nhấn Create. Hệ thống sẽ cấp cho em một chuỗi đường dẫn nằm ở ô Invoke URL dạng https://xxxx.execute-api.ap-southeast-1.amazonaws.com.
7 Thử nghiệm API Copy đường link Invoke URL dán lên trình duyệt và gõ thêm đuôi: /metrics?hero_id=74. Nếu màn hình hiển thị dữ liệu JSON dạng {"hero_id": 74, "win_rate": "52.4"} nghĩa là em đã thành công!

Em sẽ đưa mã nguồn giao diện Website tĩnh (HTML/JS) lên một S3 Bucket đặc biệt được kích hoạt tính năng Static Website Hosting.

Bước Hành động Chi tiết kỹ thuật
1 Tạo Bucket giao diện Vào S3 Console, tạo một bucket mới tên: dota2-frontend-site-tencuaban.
2 Tắt Block Public Access Vì đây là trang web công khai cho mọi người vào xem, tại mục Block Public Access, em BỎ TÍCH ô Block all public access. Nhấn tạo Bucket.
3 Cấu hình Web Hosting Mở Bucket vừa tạo > Chọn tab Properties > Cuộn xuống cuối cùng tìm mục Static website hosting > Chọn Edit > Chọn Enable.
4 Điền file mặc định Mục Index document, nhập index.html. Nhấn Save changes. Hệ thống hiển thị một đường link trang web ở dưới cùng mục này.
5 Tạo mã nguồn cục bộ Tại máy tính của em, tạo một file tên là index.html và dán đoạn mã nguồn HTML/JS ở khung bên dưới vào. (Nhớ thay thế biến API_GATEWAY_URL bằng đường link Invoke URL em vừa lấy ở bài 5.2).
6 Đẩy file lên S3 Quay lại S3 Console > Tab Objects > Nhấn Upload và tải file index.html lên.
7 Mở quyền Bucket Policy Chuyển sang tab Permissions > Mục Bucket policy > Nhấn Edit và dán đoạn mã cấu hình JSON mở quyền đọc ở bên dưới vào > Nhấn Save.

Mã JSON cho Bucket Policy (Nhớ thay dota2-frontend-site-tencuaban bằng tên bucket của em):

{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Sid": "PublicReadGetObject",
            "Effect": "Allow",
            "Principal": "*",
            "Action": "s3:GetObject",
            "Resource": "arn:aws:s3:::dota2-frontend-site-tencuaban/*"
        }
    ]
}

Khi dữ liệu tổng hợp (Metrics) đã được nạp an toàn vào Amazon DynamoDB ở Chương 4, khâu cuối cùng là xây dựng một cổng giao tiếp API và giao diện để người dùng có thể tra cứu.

Trong chương này, em sẽ thiết lập một kiến trúc API Serverless hoàn chỉnh: sử dụng AWS Lambda làm Backend bóc tách dữ liệu từ DynamoDB, đứng sau cổng kiểm soát Amazon API Gateway để tiếp nhận các yêu cầu HTTP request từ phía Website Frontend lưu trữ trên S3.
