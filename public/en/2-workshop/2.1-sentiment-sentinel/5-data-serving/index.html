Data Serving

The final step of the Data Pipeline architecture is the Presentation Layer. Instead of building complex ETL (Extract, Transform, Load) pipelines to load data into a traditional Database, the system uses Amazon Athena to query S3 JSON files directly using SQL (Schema-on-read architecture). Then, the data is loaded into the SPICE in-memory engine of Amazon QuickSight to build a BI Dashboard.

Objectives for this milestone:

  1. Define the data schema using Amazon Athena (UI Query Editor v3).
  2. Configure a unified IAM Security permission set for QuickSight.
  3. Build a BI Dashboard to monitor user sentiments.

Step 1: Initialize Schema with Amazon Athena

Amazon Athena allows you to read raw S3 data directly without managing servers (Serverless SQL).

  1. Access the Amazon Athena service on the AWS Console.

  2. Configure Output Location (Mandatory):

    • From the left menu, select Query editor.
    • On the Editor v3 screen, select the Query Settings tab on the right -> Click Manage.
    • In the Query result location field, specify an S3 path to save query logs (The athena_results folder created in step 2). Click Save.

  3. Return to the Editor tab and run the following DDL query to create the database:

    CREATE DATABASE IF NOT EXISTS sentiment_db;

  4. Select the newly created sentiment_db from the Database dropdown on the left.

  5. Run the following SQL statement to define the table, mapping it directly to the processed data directory in S3:

    CREATE EXTERNAL TABLE IF NOT EXISTS youtube_comments (
  `id` string,
  `language` string,
  `vietnamese_text` string,
  `sentiment` string
)
ROW FORMAT SERDE 'org.openx.data.jsonserde.JsonSerDe'
LOCATION 's3://<your-bucket-name>/processed_data/';

    (Note: Replace <your-bucket-name> with your actual Data Lake Bucket name).

  6. Run a test query to confirm that data is successfully loaded:

    SELECT * FROM youtube_comments LIMIT 10;

Step 2: Build a Normalized View

Instead of exposing the raw table directly to QuickSight, we will create a View. This layer renames columns to be business-user friendly and filters out erroneous records (if any) to save SPICE storage.

In the Athena Editor tab, run the following SQL query:

CREATE OR REPLACE VIEW vw_youtube_sentiment AS
SELECT 
    id AS comment_id,
    UPPER(language) AS source_language,
    vietnamese_text AS translated_summary,
    UPPER(sentiment) AS sentiment_label
FROM youtube_comments
WHERE sentiment IS NOT NULL 
  AND sentiment != 'UNKNOWN'
  AND sentiment != 'KHÔNG XÁC ĐỊNH';

Now, QuickSight will work exclusively with this clean vw_youtube_sentiment view.

Step 3: Grant S3 Access to QuickSight

This is a critical security configuration step. The QuickSight security interface requires administrators to explicitly grant Write permissions to the Athena Workgroup to avoid AccessDenied errors when loading charts.

  1. Access the QuickSight service. (Sign up for a Standard/Enterprise account if this is your first time).
  2. On the homepage, click the Avatar icon (top right corner) -> Select Manage QuickSight.
  3. In the left navigation menu, select AWS Resources.
  4. Configure access permissions (IAM Policies):
    • Check Amazon Athena. Click Next on the displayed popup.
    • Check Amazon S3. A list of your Buckets will appear.
    • CRITICAL STEP: Find and check your Data Lake Bucket to grant Read access. You must also check the Write permission for Athena Workgroup box in the adjacent column so QuickSight can log query results.
  5. Click Save.

Step 4: Import Data into the SPICE Engine

SPICE (Super-fast, Parallel, In-memory Calculation Engine) is the in-memory cache for QuickSight. Importing data into SPICE accelerates visualization response times and reduces the cost of querying S3 directly via Athena.

  1. Return to the QuickSight home page, select the Datasets tab (left menu) -> Click New dataset.
  2. Select the Data Source: Athena.
  3. Enter the data source name: YoutubeSentiment_Source -> Click Create data source.
  4. In the schema selection window:
    • Catalog: AwsDataCatalog
    • Database: sentiment_db
    • Table: youtube_comments
    • Click Select.
  5. Choose the option Import to SPICE for quicker analytics -> Click Visualize.

Step 5: Build BI Dashboard

In the Analysis screen, configure the core visualizations (Visuals) to monitor data quality:

  1. Overall Sentiment Distribution (Pie Chart):

    • Purpose: Shows the percentage breakdown of sentiments (Positive, Negative, Neutral).
    • Configuration: Drag the sentiment field into the Group/Color section. Drag the comment_id field into the Value section (defaulting to Count).

  2. Data Verification Table (Table):

    • Purpose: Lists text details to verify the accuracy of the Claude 3.5 model.
    • Configuration: Drag and drop the vietnamese_text, sentiment, author, published_at, original_text, and language columns into the Group by section.

  3. Classification by Language (Donut Chart):

    • Purpose: Monitors the language diversity of the raw comments collected from YouTube.
    • Configuration: Drag language into Group/Color, and video_id into Value.

Project Summary

At this point, the complete lifecycle of the Serverless Data Pipeline is fully implemented. The infrastructure is built strictly adhering to modern data engineering principles:

  • Decoupled Architecture: Utilizes SQS to isolate risks between the ingestion and processing layers.
  • Cost Optimization: Applies Chunking and Prompt Engineering to minimize LLM token consumption; utilizes SPICE and Schema-on-read instead of an expensive Data Warehouse.
  • Scalability: Lambda, S3, and Athena automatically scale based on the incoming JSON file volume without requiring infrastructure management.

The system is ready for automated operation (Production-ready) to process thousands of comments daily at minimal cost within the AWS Free Tier.
