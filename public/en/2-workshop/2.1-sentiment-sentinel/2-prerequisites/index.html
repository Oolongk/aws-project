Prerequisites

Before writing code, you need to prepare the resources, including AWS and Google API access.

Complete the sub-steps below in order:

To collect comments, you need to request permission from Google.

  1. Access Google Cloud Console.
  2. Go to APIs & Services > Library > Search for and enable YouTube Data API v3. Search for Youtube data API v3
  3. Go to Credentials > Create Credentials > API Key. Name the API key YoutubeAPI Key You must restrict the key. If someone accidentally obtains your key, they will not be able to use it to call other paid Google services (such as Google Maps, Google Translate, etc.).

Note: Copy this API Key and save it for later steps.

In AWS, services are isolated by default and not allowed to communicate with each other. For Lambda to call Bedrock AI, read/write files on S3, and run Athena queries, we must grant it an authorization delegation called an IAM Role.

Additionally, you need to wake up the Claude 3 model on Amazon Bedrock before implementing it in your code.

1. Activate Amazon Bedrock (Claude 3 Haiku)

Good news: Since 2026, AWS has simplified AI model access request process with Auto-enablement at the account level!

  1. Log in to the AWS Console and ensure you are in the N. Virginia (us-east-1) or Oregon (us-west-2) region.
  2. Navigate to the Amazon Bedrock service.
  3. In the left menu, search for Playgrounds and select Chat (or Text).
  4. Click the Select model button -> Choose the provider Anthropic -> Select Claude 3 Haiku.
  5. Type a test message (e.g., “Hello Claude”) and click Send. AWS will automatically approve and activate the model for you immediately!

(Note: If your account is brand new and AWS displays a form requesting Submit use case details, you can fill it out simply: Project Name, Website (you can use your Github link), and Description as “Social media data analysis for learning purposes” and click Submit).

2. Create IAM Role for Ingestor Lambda (The Miner)

The Ingestor function is responsible for collecting raw data, writing it to the Data Lake (S3), and recording statuses in DynamoDB.

  1. Navigate to AWS IAM -> Select Roles in the left menu -> Click Create role.
  2. Trusted entity type: Select AWS service.
  3. Use case: Select Lambda -> Click Next.
  4. In the search box (Permissions policies), find and check the following 4 permissions:
    • AmazonS3FullAccess
    • AmazonDynamoDBFullAccess
    • AWSLambdaBasicExecutionRole (Required permission to write execution logs).
    • AmazonSQSFullAccess
  5. Click Next -> Name the Role IngestorRole -> Click Create role.

3. Create IAM Role for Transformer Lambda (The AI Core)

This function requires higher privileges to call the AI model and trigger Athena’s Data Catalog.

  1. Repeat the role creation steps above (AWS service -> Lambda).
  2. In the search box, find and check the following 4 permissions:
    • AmazonS3FullAccess
    • AmazonBedrockFullAccess
    • AmazonAthenaFullAccess
    • AWSLambdaBasicExecutionRole
  3. Click Next -> Name the Role TransformerRole -> Click Create role.

Security Best Practice: In a corporate Production environment, you should not use *FullAccess permissions. Instead, write Inline Policies to limit access to specific S3 Buckets. However, within the scope of this Data Pipeline workshop, using Managed Policies helps avoid unnecessary “Access Denied” errors.

In a standard Data Engineer architecture, we build a central Data Lake using Amazon S3. Instead of creating multiple disjoint Buckets, we will use 1 single Bucket and divide it into directories (Folders) based on a multi-tier data management model.

Step 1: Create S3 Bucket

Note: S3 Bucket names must be globally unique.

  1. Log in to the AWS Console and access Amazon S3.
  2. Click the orange Create bucket button.
  3. Bucket name: Enter a name matching social-sentiment-datalake-yourname (Replace yourname with your name or student ID).
  4. Keep all default settings (especially the Block all public access setting).
  5. Scroll to the bottom and click Create bucket.

Step 2: Create Folders (Data Layers)

Click on the newly created Bucket, then click the Create folder button to create the following 3 folders:

  1. raw_data: The raw data storage area (Bronze Layer) collected directly from YouTube by the Ingestor function.
  2. processed_data: The sanitized and sentiment-labeled data storage area (Silver Layer).
  3. athena_results: A mandatory technical folder to store log files generated whenever AWS Athena runs queries.
