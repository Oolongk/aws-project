Data Ingestion

1. Initialize Amazon DynamoDB Storage

Amazon DynamoDB is a NoSQL database with millisecond response times, making it extremely suitable for storing continuous time-series journey data streamed from trucks.

  1. Access the AWS Management Console, search for and open DynamoDB.
  2. In the left menu, select Tables and click the Create table button.
  3. Configure the table with the following parameters:
    • Table name: IoT_Fleet_Data
    • Partition key: truck_id (Type: String) - Used to group data by truck.
    • Sort key: timestamp_ms (Type: Number) - Used to sort journey data chronologically in real-time.

  1. Under Table settings, keep the Default settings selection.

  2. Scroll to the bottom and click Create table. The creation process will take a few seconds.

2. Initialize Amazon SNS Alerting Channel

Amazon Simple Notification Service (SNS) will help us send instant email alerts to the manager when AWS Lambda detects that a truck’s temperature has exceeded the allowed threshold.

  1. Search for and open the Simple Notification Service (SNS) service.
  2. In the left menu, select Topics and click Create topic.
  3. On the Create Topic page, configure as follows:
    • Type: Select Standard (Note: You must choose Standard because FIFO topics do not support Email delivery).
    • Name: TemperatureAlerts

  1. Scroll to the bottom and click Create topic.

Registering an Email to Receive Alerts:

Once the Topic is successfully created, you will be redirected to its details page. Now, we need to declare the Email to receive alerts.

  1. Click the Create subscription button.
  2. Configure the Subscription:
    • Protocol: Select Email.
    • Endpoint: Enter your actual Email address (e.g., admin@gmail.com).

  1. Click Create subscription. The status will initially show as Pending confirmation.
  2. Email Verification: Open your email inbox, find the email with the subject AWS Notification - Subscription Confirmation, and click the Confirm subscription link.

1. Create Amazon SQS Queue

Amazon SQS acts as a “buffer” or “shock absorber” for the system. When thousands of trucks send data simultaneously, SQS captures the entire load and holds it in the queue for Lambda to process sequentially, preventing system overload.

  1. Search for and open the Simple Queue Service (SQS) service.
  2. Click Create queue.
  3. Configure the queue:
    • Type: Select Standard.
    • Name: IoT_Fleet_Queue.
  4. Keep the default settings and click Create queue.
  5. Important: Once created, copy the queue URL (looks like https://sqs...) to use during the IoT Rule configuration step later.

2. Write AWS Lambda Handler

This Lambda function is the “brain” of the system. It automatically triggers when there is data in the SQS queue, analyzes the temperature, and decides whether to send an alert.

Step A: Create the Lambda function

  1. Open the Lambda service > Click Create function.
  2. Select Author from scratch:
    • Function name: IoT_Process_Data.
    • Runtime: Select Python 3.9 or newer.
  3. Click Create function.

Step B: Grant Permissions For Lambda to read from SQS, write to DynamoDB, and publish messages via SNS, you need to grant the appropriate permissions:

  1. Go to the Configuration tab > Permissions > Click the Role name to open the IAM console.

  2. Click Add permissions > Attach policies.

  3. Search for and attach the following policies: AmazonSQSFullAccess, AmazonDynamoDBFullAccess, AmazonSNSFullAccess.

Step C: Write processing code Go back to the Lambda Code tab and paste the following code (replace YOUR_SNS_TOPIC_ARN with the ARN you copied in section 2.1):

import json
import boto3
from decimal import Decimal

dynamodb = boto3.resource('dynamodb')
sns = boto3.client('sns')
table = dynamodb.Table('IoT_Fleet_Data')
SNS_TOPIC_ARN = 'YOUR_SNS_TOPIC_ARN' # Replace with your SNS Topic ARN

def lambda_handler(event, context):
    for record in event['Records']:
        # 1. Read data from SQS
        body = json.loads(record['body'], parse_float=Decimal)
        truck_id = body['truck_id']
        temp = body['temperature']
        
        # 2. Check temperature condition (> 8 degrees C)
        if temp > Decimal('8.0'):
            message = f"WARNING: Truck {truck_id} has abnormal temperature: {temp}°C!"
            sns.publish(TopicArn=SNS_TOPIC_ARN, Message=message, Subject="Vaccine Temperature Alert")
        
        # 3. Save to DynamoDB
        table.put_item(Item=body)
        
    return {'statusCode': 200, 'body': 'Processing successful'}

Step D: Add Trigger

  1. Click Add trigger > Select SQS.

  2. Select the IoT_Fleet_Queue queue you created earlier.

  3. Click Add.

1. Create a “Thing” for the Trucks

In AWS IoT Core, each truck is treated as a “Thing”. We will create an identifier to represent the fleet.

  1. Open the IoT Core service.
  2. Go to Manage > All devices > Things > Click Create things.
  3. Select Create single thing > Click Next.
  4. Thing name: Vaccine_Truck_Fleet > Click Next.
  5. Select Auto-generate a new certificate > Click Next.

Download Security Certificates (Extremely Important):

  1. On the Download certificates page, download the following 3 files:
    • Device certificate
    • Private key file
    • Amazon Root CA 1
  2. Note: Once you leave this page, you will never be able to download the Private key again. Save them to the certs/ directory inside your project folder on your computer.

  1. Click Done. (For now, skip the Attach Policy section; we will use the default policy).

2. Configure IoT Rule (Data Routing)

This Rule will automatically capture messages sent to the telemetry/trucks topic and route them directly into the SQS queue created in section 2.2.

  1. Go to the Message routing > Rules menu > Click Create rule.

  2. Rule name: IoT_To_SQS_Rule.

  3. SQL statement: Enter the SQL query to select all data:

    SELECT * FROM 'telemetry/trucks'

  4. Click Next.

  5. Attach action: Select SQS queue.

    • Select the queue: IoT_Fleet_Queue.

  6. Click Create.

3. Retrieve Connection Endpoint

In order for the truck simulator software to know the AWS “address” to send data to, you need to retrieve your account’s unique Endpoint. In the new console interface, this information has been moved to the Domain configurations section.

  1. In the left navigation menu of AWS IoT Core, scroll to the very top.
  2. Locate the Connect menu group and select Domain configurations.
  3. In the main interface, you will see the Domain name column. This is your Endpoint address.
  4. Copy this address (looks like afjy7...-ats.iot.ap-southeast-1.amazonaws.com) and save it for use in Chapter 3.

System Deployment on AWS

In this chapter, we will configure Serverless services on the AWS Management Console. Our deployment strategy is to work backward from the end of the data flow to the beginning:

  1. Storage & Alerting (DynamoDB, SNS): Prepare the “warehouse” for journey data and set up the “broadcast” system to send emails during anomalies.
  2. Processing & Buffering (Lambda, SQS): Create a queue to ingest high-velocity data, and write a Lambda handler to check temperature logic.
  3. Ingestion (IoT Core): Create a virtual device (Thing), provision security certificates, and configure routing rules to direct the data stream into the queue.

Deploying in this sequence allows the services to easily recognize and authorize each other without encountering “resource not found” errors.
